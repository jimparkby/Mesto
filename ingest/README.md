# Импорт событий в ленту Mesto

Раз в 30 минут обходим источники, находим в новых постах анонсы тренировок и игр и добавляем их
в `public.events`. Без LLM — распознавание на правилах.

```
t.me/s/<канал> → посты → extract.ts (правила) ─┐
probeg.org (календарь) → страница забега ──────┴→ places.ts / Nominatim (координаты) → public.events
```

Источники:
- публичные Telegram-каналы (веб-превью `t.me/s/…`, без бота и аккаунта) — текст разбирается правилами;
- Telegram-группы (например, @volley_by) — у групп нет веб-превью, поэтому сообщения приносит бот Mesto:
  он добавлен в группу, получает сообщения в свой вебхук (`supabase/functions/bot`) и отдаёт их тем же правилам;
- календарь забегов «ПроБЕГ» — сайт структурированный, время и место старта берутся со страницы забега.

## Где что

- `supabase/functions/ingest/` — весь код импорта; это Edge Function `ingest`.
- `supabase/migrations/*_ingest_cron.sql` — pg_cron вызывает функцию каждые 30 минут. Вызов защищён
  секретом, который сгенерирован в базе и лежит только в Vault (`ingest_secret`).
- `supabase/migrations/*_geocode_cache.sql` — геокодирование для функции: IP Edge Functions Nominatim
  отвечает 403, поэтому запросы идут из Postgres через pg_net и кэшируются в `geocode_cache`. Ответ
  приходит асинхронно — событие с новым адресом появляется в ленте на проход позже.
- `ingest/` (эта папка) — локальный запуск того же кода в Node и тесты правил.

Что разобрано и почему пропущено — в таблице `ingest_posts` (колонка `note`). Ответы функции — в
`net._http_response` (хранятся 6 часов), запуски по расписанию — в `cron.job_run_details`.

## Локально

```bash
cd ingest
npm install
npm test        # тесты правил на примерах постов
npm run dry     # один проход без записи в базу — посмотреть, что распознаётся
npm run once    # один проход с записью (нужен .env, см. .env.example)
```

Нужен Node 24+ (TypeScript запускается напрямую).

## Деплой функции

Через CLI: `npx supabase functions deploy ingest --project-ref tztrfetnjlvjebdrrydd` (verify_jwt уже
выключен в `supabase/config.toml`). Без CLI — собрать один файл и вставить в редактор функции в дашборде:

```bash
npx esbuild supabase/functions/ingest/index.ts --bundle --format=esm --platform=neutral \
  --target=es2022 --external:'npm:*' --minify --charset=utf8 --outfile=/tmp/ingest.ts
```

Настройки — переменные окружения функции (Edge Functions → Secrets), все необязательные:
`TG_CHANNELS`, `PROBEG_CITY_IDS`, `INGEST_PAGES`, `INGEST_MAX_POST_AGE_DAYS`,
`INGEST_EVENT_STATUS` — см. `config.ts` и `.env.example`.

## Группы

`INGEST_GROUPS=volley_by:volleyball:1` — username группы, вид спорта, ветка форума (1 — общая «General»;
без номера — все ветки). Чтобы бот видел все сообщения, а не только команды: в @BotFather `/setprivacy` →
Disable (или сделать бота админом группы), затем админ группы добавляет бота. Ограничения Telegram:
- бот не видит историю — только сообщения после добавления;
- бот не видит сообщения других ботов (в @volley_by это репосты объявлений из ВК от @Volley_by_bot).

Если автор правит сообщение и дописывает «КОМПЛЕКТ» или отмену, события этого поста скрываются из ленты.

## Каналы

`TG_CHANNELS=sportdlyavseh_bel,olympicteamby,mst_gov_by,minskafisha,football_minsk:football`

- Обычный канал (афиша, городские новости) — пост берётся, только если в нём есть слова про спорт
  и призыв поучаствовать; спектакли, концерты, билеты на матч отсеиваются.
- Тематический канал — `имя:вид_спорта`. Там посты часто вообще не называют вид спорта
  («05.06 пн 20.30—22.00 ФОЦ Машерова»), поэтому он подставляется из настроек.

## Что распознаётся

| Что | Примеры |
|---|---|
| Дата | `18.10.2026`, `19.10`, `24 октября`, `завтра`, `в субботу` |
| Время | `в 9:30`, `в 19.00`, `20.30—22.00` (заодно длительность), `в 7 вечера` |
| Место | известные места из `places.ts`, строки `📍 …` / `Место: …`, адреса `ул. … 12`, остаток строки с датой |
| Цена, места, уровень | `бесплатно`, `по 12 р`, `до 14 человек`, `для новичков` |

В тематических каналах и группах (`имя:вид_спорта`) сообщения обычно без заголовков и пишутся как в чате:
«Сегодня на Солтыса 187/1 одно место в связку, Д4, 21-23:00, 11р». Правила понимают адреса без «ул.»,
время вида «21-23:00», «с 19 до 21», «в 18-45», уровни Д1–Д5; «КОМПЛЕКТ» и «ищу, где поиграть» отсеиваются.

Расписание («19.10 … / 21.10 …») превращается в несколько событий; если все даты в посте одинаковые —
это одно событие. Отсеиваются отмены и переносы, посты «расписание откроется в 10:00», розыгрыши призов
и новости большого спорта (медали, сборные), если в них не зовут участвовать. Если в анонсе нет даты, времени
или места, его пропускаем.

Неуверенные случаи (дата только по дню недели, вид спорта «другое») добавляются **скрытыми**: их
одобряет админ на странице модерации. `INGEST_EVENT_STATUS=hidden` отправляет на модерацию всё подряд.

Дубли отсекаются: событие с тем же видом спорта и временем в радиусе 500 м уже есть — второе не добавляется.

## ПроБЕГ

`PROBEG_CITY_IDS=1581` — id городов из адреса `probeg.org/races/city/<id>/` (1581 — Минск). Берутся только
будущие забеги. Если время или место старта на странице ещё не указаны, забег проверяется снова в следующий проход.

## Как улучшать

- Место не нашлось на карте → добавьте его в `places.ts` (название, варианты написания, координаты из OSM).
- Пост распознан неправильно → добавьте его в `test/extract.test.ts` и поправьте правила в `extract.ts`.
- Новый тип источника (Instagram, сайт) → модуль в `sources/`, который возвращает `SourcePost[]`.
  Текстовые посты разберут правила; структурированный сайт может сразу заполнить `SourcePost.events`
  (как `sources/probeg.ts`).
